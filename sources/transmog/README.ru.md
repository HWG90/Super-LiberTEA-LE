# HD2 Transmog

[English](https://github.com/tyrypyrking/HD2-Transmog/blob/v0.2.4/README.md) · **Русский**

Сочетайте внешний вид, базовые характеристики и пассивный эффект доступной вам брони в **Helldivers 2**. Сохраните комбинацию как Custom Variant и экипируйте её в арсенале игры.

> [!IMPORTANT]
> Нужны отдельно установленный **Bingus Shared Loader v15+ / API 1** и **Arsenal** для описанного ниже способа установки. Включите одну копию загрузчика вместе с Transmog. При стандартном приоритете Arsenal поставьте загрузчик **последним, внизу списка**, затем выполните **Purge / Deploy**. Если включён приоритет первого мода, поставьте его первым. Подробнее — в [инструкции загрузчика](https://github.com/CowboyBingus/BingusSharedLoader/blob/main/INSTALL.txt).

**Версия: 0.2.4 Experimental.** Это экспериментальный предварительный релиз. Наборы одежды и мультиплеер ещё проходят проверку; перед установкой прочитайте [известные ограничения](#совместимость-и-ограничения).

## Возможности

- **Независимый выбор брони:** внешний вид, базовые характеристики и пассивный эффект берутся из доступного вам снаряжения. Базовые характеристики не включают бонус пассивного эффекта донора: выбранный эффект применяется отдельно.
- **Карточки в арсенале:** просматривайте сохранённые варианты, их характеристики и пассивные эффекты, затем нажимайте Apply. Создание карточки не экипирует броню.
- **Мышь и контроллер:** стандартная сетка внешних видов и пошаговый редактор, в том числе на сверхшироких экранах.
- **Варианты шлемов и плащей:** доступны, когда в соответствующем слоте обнаружены поддерживаемые изменения пассивных эффектов или веса. Transmog сам не добавляет пассивные эффекты обычным шлемам и плащам.
- **Сохранение комбинаций:** варианты брони, шлемов и плащей остаются после перезапуска. Проверенный вариант основной брони может автоматически восстановиться на корабле.
- **Дополнительные интеграции:** точные комбинации брони в совместимых пресетах DiverKit; экспериментальные наборы одежды и генерация миниатюр.

## Установка

Игрокам нужны готовые ZIP-архивы. Python, LuaJIT и репозиторий исходников требуются только для сборки мода. Названия кнопок ниже оставлены на английском, чтобы их можно было найти в интерфейсе.

1. **Закройте Helldivers 2.** Откройте Arsenal и используйте его для этой установки.
2. Скачайте готовый ZIP **HD2 Transmog Foundation** со [страницы Files](https://www.nexusmods.com/helldivers2/mods/16633?tab=files) или из [релиза GitHub](https://github.com/tyrypyrking/HD2-Transmog/releases). Нужен архив мода, а не **Source code**. Если версия отличается от этой инструкции, учитывайте примечания её релиза.
3. Отдельно скачайте [Bingus Shared Loader](https://github.com/CowboyBingus/BingusSharedLoader). Transmog требует **v15 или новее с API 1**; следуйте актуальной инструкции загрузчика. Arsenal не устанавливает эту зависимость автоматически.
4. Импортируйте оба ZIP в Arsenal и включите **HD2 Transmog Foundation** и **Bingus Shared Loader**. При обновлении заменяйте существующую запись; не оставляйте включёнными несколько версий.
5. При стандартном порядке загрузки поставьте **Bingus Shared Loader последним**. При приоритете первого мода — первым. Номера патчей назначает Arsenal.
6. Выберите [настройки Transmog](#настройки), затем выполните **Purge / Deploy**, пока игра закрыта.
7. Запустите игру. На корабле откройте **Armory → Equipment → Armor** и найдите **Custom Variants** с карточкой **+**.

Загрузчик также описывает установку через HD2MM. Настройки и проверки этого проекта ориентированы на Arsenal; выше приведён именно этот способ.

## Создание и экипировка варианта

1. На корабле откройте **Armory → Equipment → Armor**, затем **Custom Variants → +**.
2. Выберите доступный **внешний вид**. Если модифицированная модель поддерживает переключаемые детали, этап **Set the look** позволит настроить их.
3. Выберите **базовые характеристики**, затем **пассивный эффект**. Этап характеристик пропускается, если он отключён в Arsenal или доступен только один проверенный вариант.
4. Нажмите **Create**, чтобы сохранить комбинацию.
5. Выберите новую карточку и нажмите **Apply**, чтобы экипировать её.

**Remove variant** удаляет карточку, не меняя надетую броню. В предмиссионном Equipment можно выбрать сохранённый вариант основной брони; создание и удаление доступны в арсенале корабля. Новое полученное снаряжение становится доступно автоматически; если стандартный список миниатюр не обновился, откройте категорию заново.

Для шлемов и плащей откройте соответствующую вкладку: **+ → Look → Passive → Create**, затем карточку и **Apply**. Характеристики определяются внешним видом. У каждого слота свои доноры и сохранения. Обычные варианты шлемов и плащей нужно применять заново после перезапуска игры.

### Управление с контроллера

| Кнопка | Действие |
| --- | --- |
| Крестовина / левый стик | Перемещение фокуса |
| A | Выбор или нажатие выделенной кнопки; нажмите и отпустите для Apply готовой выбранной карточки |
| B | Назад; на первом этапе — отмена |
| Y | Отмена создания |
| LB / RB | Переключение страниц вариантов |
| Влево / вправо в списках характеристик и эффектов | Переход между вариантами и кнопками действий |

После выбора пассивного эффекта фокус переходит на **Create**; для подтверждения нажмите A ещё раз. В **Set the look** влево/вправо меняет значение выбранной строки, а вниз после последней строки переводит фокус на **Next**. Навигация WASD следует выбору в родной сетке; подтверждайте действие мышью или контроллером. Проверены XInput/Steam Input; другие способы подключения контроллера не проверены.

## Настройки

Три настройки независимы. Изменяйте их в **Arsenal → Options**, выполняйте Deploy при закрытой игре и перезапускайте её. Характеристики ранее сохранённых комбинаций не меняются.

| Настройка Arsenal | По умолчанию | Действие |
| --- | --- | --- |
| **HD2 Transmog Foundation** | **Independent armor stats (default)** | Отдельный выбор внешности, характеристик и эффекта. **Disable armor stat selection** берёт характеристики выбранного внешнего вида. |
| **Helmet and cape variants** | **On (default)** | Включает редактор при обнаружении поддерживаемых изменений в этих слотах. После обновления могло сохраниться Off. |
| **Armor thumbnail passive icons** | **On (default)** | Значки эффектов на миниатюрах брони. Off не скрывает значки в выборе пассивного эффекта и подробной информации. |
| **Armory interface** | **On (default)** | Свои карточки, конструктор и готовые превью в Оружейной. Off оставляет стандартную Оружейную; сохранённые варианты и API одежды продолжают работать. |
| **Developer tools** | **Off (default)** | Отладочный мост и внутриигровой набор тестов. Не включайте без просьбы сопровождающего. |

При наличии дополнительного **Mod Options Menu** в **Options → MODS → HD2 Transmog** доступны настройки предпросмотра и экспорт журналов:

- **Export logs to Desktop → Export now**, затем **Apply** сохраняет отчёт `HD2-Transmog-Logs-*.txt` на рабочий стол. Строка показывает результат; действие можно повторить. В Windows используется настроенный рабочий стол, в том числе перенаправленный; в Linux/Proton — путь из `user-dirs.dirs`, по умолчанию `~/Desktop`. Отчёт содержит полные доступные файлы `.log` загрузчика и модов, включая предыдущие сеансы Transmog. Недоступные файлы отмечаются в отчёте; при частичном экспорте строка сообщает об этом. Старые отчёты не перезаписываются, автоматической отправки нет. Приложите файл к сообщению об ошибке. Экспорт не восстанавливает уже удалённые или незаписанные события. Без Mod Options Menu или при ошибке экспорта соберите журналы вручную, как описано ниже.
- **Clear saved data → Clear now**, затем **Apply**, начинает с чистого листа: сохранённые варианты, надетые образы и дома одежды откладываются копиями с именами `-cleared-<время>` в папке состояния Transmog, записываются свежие файлы, и строка просит перезапустить игру. Ничего не удаляется безвозвратно.

- **Generated previews: Off (по умолчанию)** оставляет уже сохранённые Transmog изображения на месте, а отсутствующую карточку модового образа — пустой; ничего не рендерится. **On** рендерит карточки и плитки снаряжения на странице Оружейной для модовых образов через полный конвейер игры, пока открыт список предметов Оружейной.
- **Mod author's choice**, **Force HD2** и **Force Studio** задают стиль миниатюр. У каждого стиля свой дисковый кэш.
- **Regenerate now** проверяет совместимость рендера и запускает пересоздание миниатюр. Держите список предметов в арсенале открытым. Старое изображение остаётся до успешного сохранения нового; кэши других стилей сохраняются.
- **Armory 3D preview: Game default** (по умолчанию) оставляет большую модель Оружейной игре. **Full render** рисует её через полный конвейер рендера игры с освещением и цветокоррекцией Transmog; нужно временное сглаживание.

Недостающие видимые миниатюры создаются по мере необходимости. При запуске с готовым кэшем рендер миниатюр не инициализируется; после генерации он освобождается. Пока изображение нужного варианта не готово, показывается индикатор загрузки.

## Обновление и удаление

### Обновление

Закройте игру, импортируйте новый ZIP **как обновление той же записи Transmog**, оставьте загрузчик включённым, выполните Purge / Deploy и перезапустите игру. При переходе со старых объединённых настроек Arsenal один раз заново выберите все три независимые настройки.

**0.2.3 → 0.2.4:** всё сохраняется. При первом запуске сохранённые варианты копируются в `transmog-v3.state` (шлемы и плащи — в `helmets-v3.state` и `capes-v3.state`), который пишут только 0.2.4 и новее; старые файлы остаются в точности как были, поэтому при возврате 0.2.3 и более ранние версии продолжают работать с ними, а сохранённое в любой из версий ждёт её. **0.2.2 → 0.2.3:** всё сохраняется; формат сохранений не изменился. **0.2.1 → 0.2.2:** сохранённые варианты, экипировка и готовые миниатюры сохраняются. Пустой эффект Standard Issue больше не отмечается значком в сетке.

**0.2.0 → 0.2.1:** сохранённые варианты и экипировка сохраняются. Старые сгенерированные миниатюры сбрасываются, чтобы убрать изображения, созданные из изменённых исходных шаблонов; держите список предметов открытым, пока правильные изображения автоматически генерируются заново.

**0.1.5 → 0.2.0:** ручная конвертация и повторное создание вариантов не нужны. Имена, внешность, характеристики и эффекты сохраняются. При чтении назначаются постоянные идентификаторы; следующая запись использует новый формат. Перед заменой старого сохранения Transmog сохраняет и проверяет исходные байты в `<name>-v1.state`; если такая копия уже есть и отличается, создаёт дополнительную с суффиксом на основе содержимого. При ошибке записи предыдущий основной файл остаётся. Начиная с 0.2.4 повреждённый файл откладывается в сторону и используется новейшее исправное сохранение; запись никогда не отключается.

Для возврата к 0.1.5 восстановите соответствующие резервные копии старого формата при закрытой игре: 0.1.5 не читает новый формат.

### Удаление

Закройте игру, отключите Transmog и зависящие от него наборы одежды в Arsenal, затем выполните Purge / Deploy. Оставьте Bingus Shared Loader включённым, если он нужен другим модам.

Варианты остаются в `%LOCALAPPDATA%\CowboyBingus\Helldivers2\Transmog`. Сохраните папку, если планируете вернуться к моду. Без Transmog его файлы восстановления игнорируются; игра сохраняет обычные идентификаторы снаряжения.

## Совместимость и ограничения

### Наборы одежды — экспериментальная функция

Совместимые наборы появляются в **Modded Armors** после Custom Variants. Устанавливайте их ZIP через Arsenal вместе с Transmog и загрузчиком. Архив только для проверки регистрации не содержит пригодной для использования одежды: для экипировки нужна проверенная привязка к игровым данным. Порт Sister Lacrima содержит броню и шлем с авторской моделью Lean для обоих типов тела; плащ в исходном наборе отсутствует.

Синхронизация одежды реализована и проверялась на двух компьютерах. Сессии на три/четыре игрока, смена хоста и повторное подключение ещё не прошли полную проверку. Для отображения пользовательских моделей участникам нужны совместимые наборы. Это отдельная система от старого appearance API, который поддерживает только регистрацию. Подробнее — в [справочнике clothing API](https://github.com/tyrypyrking/HD2-Transmog/blob/v0.2.4/sdk/API.ru.md#clothing-api-2).

### DiverKit — необязательная интеграция

Экипируйте нужный вариант через Transmog, затем сохраните или перезапишите пресет DiverKit. Сохраните соответствующее определение в Transmog. Старые пресеты, содержащие только стандартный ID брони, нужно записать заново; это также требуется после удаления или изменения определения. Если исключить **Armor** из пресета, броня не меняется.

Пресеты модифицированной брони сохраняют UUID одежды и идентификатор варианта, а актуальную запись для отображения определяют при применении. Поиск интерфейса учитывает длинные цепочки обработчиков и таблицы обработчиков C-Rig без привязки к номеру выпуска Transmog. Отсутствующая или изменённая привязка блокирует операцию до записи экипировки.

Совместимость проверяется по доступным возможностям во время работы. Сохранение и применение пользовательской брони проверены в игре с DiverKit **8.10.4**; автоматические проверки также включают **8.8.1** и **8.10.1**. Это не гарантия для всех версий. При несовместимом интерфейсе появляется уведомление; если точку сохранения удалось определить, запись блокируется, чтобы не потерять комбинацию.

### Моды пассивных эффектов и Mod Bindings Menu

Отдельный Mod Bindings Menu совместим с Transmog. Используйте либо отдельный пакет, либо соответствующую опцию Megapack.

Эффекты шлемов и плащей определяются по данным игры без привязки к конкретному моду. Изменение числовых эффектов не отменяет владение предметом. Позднее назначение пассивного эффекта принимается только для записей, которым Transmog не назначал собственный эффект; явный выбор варианта остаётся защищён. Информационная панель другого мода может использовать исходные эффекты и расходиться с выбранным эффектом Transmog. Недоступные доноры сохранённых вариантов не заменяются автоматически.

### Текущие ограничения

- **Доступность и экипировка:** перед записью/применением повторно проверяется владение обычными внешними видами, донорами характеристик и эффектами. Недоступные комбинации остаются сохранёнными. Восстановление основной брони ждёт свободного состояния на корабле, ожидаемой игровой записи-носителя и корректного доступного определения. Прерванная попытка не повторяется автоматически при следующем запуске.
- **Шлемы и плащи:** автоматическое восстановление обычных вариантов и их редактирование перед миссией не реализованы. У экспериментальной зарегистрированной одежды отдельный механизм восстановления с проверками. Работа пассивных эффектов в бою и их сочетаний зависит от игры и мода, добавившего эффекты; отображение в интерфейсе не доказывает работу в бою.
- **Предпросмотр:** крупные плитки Armor/Helmet/Cape используют кэш изображения надетой модифицированной вещи. Для раздела Armor создаётся отдельное изображение со стандартным шлемом B-01; надетый шлем не меняется. Если изображения ещё нет, откройте список предметов для генерации; до этого показывается индикатор загрузки. Генерация проверена в игре при 1920×1080 на Linux/Proton и 3840×2160 на Windows, в дополнение к прежним проверкам 2560×1440. Для других размеров, включая ultrawide, есть автономные проверки кадрирования, но аналогичная проверка в игре ещё не выполнена. При массовой генерации большая модель может удерживать последний кадр. Полный цикл регенерации ещё нужно повторно проверить после сообщения о вылете.
- **Производительность:** дополнительная нагрузка в арсенале остаётся. Обнаружение входа в меню может занимать до 250 мс. В замере пересоздания 40 карточек результат улучшился с 15 FPS / 62 секунд до 65 FPS / 14,4 секунды на проверенной системе. Это не подтверждает исправление отдельно заявленной проблемы низкой загрузки GPU/FPS.
- **Обновления игры:** совместимость низкоуровневых привязок проверяется по исполняемому файлу. После структурных изменений может понадобиться обновление Transmog. Не проверены все миссии, сочетания эффектов и других модов; случай двойного пассивного эффекта ещё требует проверки в окружении, где он воспроизводится.

## Решение проблем

| Симптом | Что проверить |
| --- | --- |
| Нет Custom Variants / + | Оба мода включены, загрузчик один и имеет приоритет, Purge / Deploy выполнен при закрытой игре. Начните с вкладки Armor в арсенале корабля. |
| Нет редактора шлемов/плащей | **Helmet and cape variants → On**. В слоте должны быть поддерживаемые изменения эффектов/веса; Transmog сам их не добавляет. После изменения каталога откройте арсенал заново. |
| Пропала сохранённая карточка | Проверьте владение предметами и установку нужных наборов одежды. Недоступные определения сохраняются; не удаляйте папку сохранений. |
| Одежда из набора недоступна | Проверьте `clothing-status.txt` и причину ошибки привязки в журнале. Регистрация ещё не означает готовность к отображению. |
| Миниатюра отсутствует или неверна | Держите список предметов открытым. Перед **Regenerate now** проверьте стиль и диагностику рендера. У крупных плиток разделов отдельное известное ограничение. |
| Пресет DiverKit теряет комбинацию | Экипируйте вариант в Transmog и перезапишите пресет с совместимым интерфейсом DiverKit. Не удаляйте определение в Transmog. |
| "Saved variants restored from a backup" или "Saved variants could not be read" | Сохранённый файл был повреждён, например программой синхронизации или прерванной записью. Transmog хранит три последних сохранения и взял самое новое исправное или начал с чистого листа, если исправных не было; сохранение продолжает работать, делать ничего не нужно. Повреждённый файл остаётся рядом с остальными под именем `<имя>-damaged-<время>.state` и попадает в экспорт журналов. |

Используйте [формы сообщений об ошибках](https://github.com/tyrypyrking/HD2-Transmog/issues/new/choose). Укажите версии мода, загрузчика и игры, включённые моды, шаги воспроизведения, ожидаемый и фактический результат. По возможности приложите файлы проблемного запуска:

```text
%LOCALAPPDATA%\CowboyBingus\Helldivers2\
├── Logs\
│   ├── HD2Transmog.log
│   ├── HD2Transmog.previous.log   (и .previous-2.log, .previous-3.log)
│   └── BingusSharedLoader.log
└── Transmog\
    ├── problems.txt              (что вам показывали и проблемы сеанса; отчёт начинается с обоих блоков)
    ├── health.txt
    ├── game-contract.txt
    ├── STATUS.txt
    ├── clothing-status.txt       (для наборов одежды)
    ├── transmog-v3.state         (ваши сохранённые варианты; -gen1…-gen3 — предыдущие сохранения)
    ├── transmog-v3-damaged-*.state (повреждённый файл, сохранён, если есть)
    ├── transmog.state, transmog-v1*.state (сохранены прежними версиями, остаются как были)
    └── equipped*.state, clothing-homes.state, preview-*.state
```

В Proton отчёт сохраняется на рабочий стол Linux (путь из `user-dirs.dirs`, иначе `~/Desktop`), а не внутрь префикса Wine; в заголовке отчёта указано, какой рабочий стол выбран и почему. Отчёт **Export logs to Desktop** открывается сводкой проблем сеанса — тем же блоком, что лежит в `problems.txt`; сам файл остаётся в `Transmog\` для чтения и повторно не копируется. Кроме журналов, отчёт содержит файлы из `Transmog\`: `health.txt`, `game-contract.txt`, `STATUS.txt` и `clothing-status.txt`, если они есть, список всех файлов сохранений `.state` с размером и первой строкой и копию `transmog.state` с отложенными оригиналами `transmog-v*.state`, до 64 КиБ каждый. В файлах сохранений только идентификаторы комплектов, слова переключателей и названия, которые вы дали вариантам; названия вариантов попадают в отчёт. Недоступные файлы отмечаются в отчёте. Отчёт начинается с двух блоков: `Shown to the player:` (каждое сообщение, которое мод вам показал) и `Problems this session:` (каждый записанный сбой, когда впервые и сколько раз), затем идут журналы, файлы состояния (никогда не записанный файл отмечен как `[MISSING: <имя>]`), список файлов сохранений и копия `transmog.state`. `catalog.helmets` и `catalog.capes` сообщают число проверенных и имеющихся предметов и найденные игровые изменения; `helmet.transmog_enabled` фиксирует настройку Arsenal.

Отсутствие журналов не мешает сообщить об ошибке. Сохраняются текущий журнал Transmog и три предыдущих. `state.loaded` показывает число сохранений; `presentation.saved` различает сохранённые, показанные и недоступные карточки.

## Документация API

Lua API работает внутри игры через `HD2Transmog`; это не HTTP-сервис. Версии API загрузчика, одежды, внешних видов и сохранений — отдельные контракты.

| API | Статус и назначение | Документация |
| --- | --- | --- |
| `HD2Transmog.clothing` — API **2**, asset ABI **1** и **2** | Экспериментальная регистрация наборов, управление внешностью, сохранённые настройки и события; с asset ABI 2 ресурсы набора не занимают память, пока его вид не появится на экране | [English](https://github.com/tyrypyrking/HD2-Transmog/blob/v0.2.4/sdk/API.md#clothing-api-2) · [Русский](https://github.com/tyrypyrking/HD2-Transmog/blob/v0.2.4/sdk/API.ru.md#clothing-api-2) |
| `HD2Transmog.equipment` — API **1** | Только чтение: каталог игры, что надето на локальном игроке и когда рядом с экипировкой можно безопасно действовать | [English](https://github.com/tyrypyrking/HD2-Transmog/blob/v0.2.4/sdk/API.md#equipment-api-1) · [Русский](https://github.com/tyrypyrking/HD2-Transmog/blob/v0.2.4/sdk/API.ru.md#equipment-api-1) |
| `HD2Transmog.equipment` — API **2** | Экспериментально, для модов, которые сами меняют данные экипировки: чем считается вариант в игре, событие на каждое его изменение и именованные полномочия с одним держателем у каждого | [English](https://github.com/tyrypyrking/HD2-Transmog/blob/v0.2.4/sdk/API.md#equipment-api-2) · [Русский](https://github.com/tyrypyrking/HD2-Transmog/blob/v0.2.4/sdk/API.ru.md#equipment-api-2) |
| `HD2Transmog.health()` | Что работает и что отключено, по именам | [English](https://github.com/tyrypyrking/HD2-Transmog/blob/v0.2.4/sdk/API.md#health) · [Русский](https://github.com/tyrypyrking/HD2-Transmog/blob/v0.2.4/sdk/API.ru.md#health) |
| `HD2Transmog.previews` | Генерация/состояние миниатюр и настройки предпросмотра; проверяйте наличие методов | [English](https://github.com/tyrypyrking/HD2-Transmog/blob/v0.2.4/sdk/API.md#preview-api) · [Русский](https://github.com/tyrypyrking/HD2-Transmog/blob/v0.2.4/sdk/API.ru.md#preview-api) |
| `HD2Transmog.appearances` — API **1**, asset ABI **1** | Черновой API регистрации и просмотра; независимое отображение недоступно | [English](https://github.com/tyrypyrking/HD2-Transmog/blob/v0.2.4/sdk/API.md#appearance-api-1) · [Русский](https://github.com/tyrypyrking/HD2-Transmog/blob/v0.2.4/sdk/API.ru.md#appearance-api-1) |

Начните с [быстрого старта API](https://github.com/tyrypyrking/HD2-Transmog/blob/v0.2.4/sdk/API.ru.md#quick-start).
